# Polaris K80 · 手指原生交互重构

**设计立场：不再以页面跳转组织交互，而以屏幕空间与拇指手势组织功能。**
这次为独立 UI 层，复用现有 `window.polarisStore`；**Mac 端不修改**。

## 触控结构
- **左侧 4 个快捷操作**：日程、行动、心情、专注。点按打开原位底部抽屉。
- **底部长胶囊**：手指拖过效率、灵气、看板三个物理区域，松开确定中枢；视觉采用位置弹簧反馈。
- **底部圆胶囊**：没有“+”号；花朵图标按住 210ms（或直接滑动超过 16px）展开花瓣快捷菜单；手指移动高亮目标并震动反馈，松手执行。无鼠标用户仍可以点按打开再选。
- **右下小圆快捷球**：可拖动并自动吸附左右边缘；轻点打开快捷想法记录。
- **原位展开**：任务、日程、心情、专注都由底部抽屉操作，不跳新页面；抽屉手柄下滑 74px 关闭。

## 真实数据
生产环境直接使用现有 PolarisStore 中的 `schedules / tasks / moodLogs / ideas / focusLogs`，数据修改调用既有 `addSchedule / addTask / toggleTask / logMood / addIdea / recordFocus` 方法；
可视化的日程圈直接取当天真实时间数据。保留既有同步边界与用户数据，不添加虚假的飞书连接状态。离线预览 HTML 内使用另外的演示数据并明确标注。

## 真机适配
屏幕内禁用主舞台纵向页面滚动；抽屉内部允许原生滚动；浮动球与胶囊使用 Pointer Events 和触觉反馈；
为 Android 安全区留白，支持小于 740px 高度的屏幕；尊重 reduced-motion。
测试过 320×690、360×780、390×844、430×932 模拟视口与基本滑选交互；
**仍需 REDMI K80/澎湃 OS 真机的多指、系统返回、状态栏、键盘与性能回归。**

## 回退方式
移除两个移动端 HTML 中加入的 `polaris-native-shell.css` 和 `polaris-native-shell.js` 引用即可恢复已有 7 页面 UI；
原文件、核心数据库、Mac MVP 均未改动。
